Architecting BugSmasher: Zero-Dependency React Game Engines & 678 Automated Tests

How we built a high-performance React game engine with 646 Vitest units, 32 Firebase E2E simulations, custom canvas state management, and 60fps rendering without external game libraries.

The Challenge: React vs. Game Loops

React is fundamentally built for declarative UI rendering, state diffing, and component trees. Game loops require deterministic requestAnimationFrame ticks, mutable transform matrices, and low-latency physics calculations. Reconciling these two paradigms usually results in either heavy abstraction layers or janky frame drops.

When we set out to build BugSmasher under Hope Theory, the constraint was absolute: deliver a buttery 60fps arcade experience inside a modern web app while maintaining 100% test coverage and robust backend persistence.

Architecture & State Management

Instead of relying on heavy third-party game frameworks like Phaser or Pixi.js which bloat bundle sizes and complicate React state synchronization, we architected a bespoke rendering pipeline:

  • Core Game Loop: Implemented via a custom useGameLoop hook leveraging requestAnimationFrame with delta-time normalization to prevent speed variations on high-refresh-rate displays.
  • State Separation: UI overlays (scoreboards, health bars, combo multipliers) live in optimized React state, while high-frequency sprite coordinates and collision boxes live in a typed Float32Array memory buffer.
  • Zero Runtime Bloat: Total bundle size under 120KB gzipped, loading instantly even on 3G connections in Dhaka.
// Simplified Game Loop Architecture
class GameEngine {
  constructor(canvas, config) {
    this.canvas = canvas;
    this.ctx = canvas.getContext('2d');
    this.entities = new Map();
    this.lastTime = performance.now();
  }

  tick = (currentTime) => {
    const dt = (currentTime - this.lastTime) / 1000;
    this.lastTime = currentTime;
    
    this.update(dt);
    this.render();
    
    this.animationId = requestAnimationFrame(this.tick);
  }
}

Testing Strategy: 678 Automated Suites

Quality in game development is notoriously difficult to guarantee without manual QA. We solved this by treating game mechanics as pure deterministic functions that can be tested in headless Node environments.

"If your game logic is tightly coupled to DOM elements or requestAnimationFrame, your tests will be brittle. Decouple physics from rendering, and you can test 10,000 game ticks in under 2 seconds."

Our test suite comprises 646 Vitest unit tests covering collision detection matrices, score multipliers, state transitions, and audio trigger queues, alongside 32 Firebase integration tests verifying multiplayer state synchronization and leaderboard commits.

Key Takeaways & Lessons Learned

  1. Immutability has a cost: In high-frequency render loops, avoid deep object spreads. Pre-allocate arrays and reuse object pools for particles and entities.
  2. Test-driven game dev works: Writing collision and scoring rules in Vitest before touching canvas rendering saved countless hours of debugging.
  3. Performance budgets matter: Monitoring frame budget (16.6ms per frame) ensured zero layout thrashing.
